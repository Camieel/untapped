Help Document & FAQ

Solutions to common carrier errors, address validation rules, and support contacts

1. Frequently Asked Questions (FAQ)

Why does the shipping widget display an "Incomplete Address" warning?

The shipping carrier APIs (PostNL, DHL, SendCloud, MyParcel) strictly require a valid street address, house number, postal code, and city to calculate shipping routes. If any of these mandatory fields are empty or incomplete in your Zoho CRM Sales Order record, the widget automatically blocks label generation to prevent carrier rejection fees. Update the address fields on the order and click 🔄 Retry in the widget.

Why is my Mailbox Package rejected by the widget or carrier?

In the Benelux region, carriers enforce strict maximum dimensions for mailbox parcels (specifically a maximum thickness of 3.2 cm for PostNL and MyParcel). If the height entered in the widget exceeds 3.2 cm, our system will prevent submission and alert you to adjust the package dimensions or select a standard parcel service.

Why isn't the PDF shipping label appearing in my order Attachments immediately?

While carriers like PostNL and MyParcel generate PDF labels synchronously (instantly), certain providers—most notably DHL—process shipping labels asynchronously in their backend queue. If the widget displays "⏳ Label is being processed...", wait 5 to 10 seconds and press F5 (or refresh your browser window). The PDF label will automatically appear under your Zoho CRM Attachments list once the carrier completes generation.

Can I generate multiple shipping labels for a single Zoho CRM order?

Yes! If an order consists of multiple boxes or requires split fulfillment, open the shipping widget on the active order and click the ➕ Extra Label button at the bottom of the dashboard. This temporarily overrides the active shipments view and allows you to generate an additional, independent tracking number and label for the second package.

How do I cancel or void a shipping label that was created by mistake?

Open the shipping widget on the Sales Order, locate the specific label under "Active Shipments", and click the trash icon labeled 🚨 Cancel. Confirm the cancellation prompt. The extension will send an API cancellation request to the carrier to void the barcode before it is scanned by the driver. Note: Labels can usually only be voided before they are physically scanned at the sorting depot.

2. Troubleshooting Carrier API Errors

When an API error occurs, the widget will display the raw rejection message returned by the carrier. Reference the common error codes below to resolve the issue:

ERROR: Unauthorized / Invalid API Key
The widget says "No API Key found" or "Authentication Failed".

This indicates that your carrier credentials are missing or incorrect. Please contact your system administrator to verify that your exact Public Key and Secret Key are saved correctly inside the Carrier_Configs custom module in Zoho CRM.

ERROR: Invalid Postal Code Format
The carrier rejects the shipment with a postal code or country error.

Ensure that the postal code matches the official format of the destination country. For Dutch (NL) addresses, ensure there is a valid 4-digit and 2-letter combination (e.g., 1000 AA). For international world parcels, verify that the two-letter ISO country code (e.g., US, DE, BE) is selected correctly in CRM.

ERROR: Weight Out of Bounds
The carrier rejects the label stating the weight is invalid.

Check the weight field in the widget modal. Carriers reject labels with a weight of 0.00 kg or negative values. If your Zoho order items do not have pre-configured weights, manually enter a valid weight (e.g., 1.50 kg) before clicking create.

If you encounter persistent technical bugs, require custom field mapping, or need assistance adapting the extension to your specific warehouse workflow, our development team is ready to help.
