Admin Guide

Installation, API configuration, and permission mapping for system administrators

1. Prerequisites & System Requirements

Before installing the Multi-Carrier Shipping & Labels extension, verify that your Zoho CRM environment meets the necessary system requirements. The installer requires administrative privileges to create custom modules and buttons.

  • Supported Zoho CRM Editions: Professional, Enterprise, Ultimate, Zoho One, or Zoho CRM Plus. (Standard and Free editions are not supported due to their lack of Custom Deluge Functions and Embedded UI Widgets).
  • Required User Role: You must be signed in as a Zoho CRM **Administrator** during installation.
  • Module Access: Ensure the Sales_Orders, Contacts, and Accounts standard modules are active in your CRM workspace.

2. Installation & Profile Permissions

To deploy the extension from the Zoho Marketplace:

1
Launch the Marketplace Installer Navigate to the official Marketplace installation link (or open Settings → Setup → Marketplace → All inside Zoho CRM and search for "Multi-Carrier Shipping").
2
Agree to Terms & Select Profiles Review the Terms of Service and check the agreement boxes. Choose which user profiles should be granted access to the fulfillment features. We recommend selecting "Install for specific profiles" and granting access to Administrator, Standard, and Sales Management roles.
3
Confirm Automated Deployment Click **Install**. The setup engine will automatically generate the custom button on the Sales Orders module, install the Carrier_Configs custom storage module, and register the underlying Deluge backend scripts.

3. Configuring Carrier API Keys

To authorize label generation and live Track & Trace synchronization, you must link your active shipping carrier accounts by storing your developer API credentials in Zoho CRM.

Security Note: API credentials are stored in the custom module Carrier_Configs. We recommend restricting READ/WRITE access to this specific module to **Administrator profiles only** to prevent unauthorized modification of your shipping contracts.

Follow these steps to configure your carriers:

  1. Inside Zoho CRM, go to the top navigation bar and open the **Carrier_Configs** module (if hidden, check under the More (...) dropdown menu).
  2. Click **+ Create Carrier Config** to add a new connection record.
  3. In the **Carrier Name** field, type the exact identifier for your provider (case-sensitive). Use one of the supported names below:
    • SendCloud
    • MyParcel
    • PostNL
    • DHL
  4. In the **API Key Username** field, paste your Public API Key or developer access token obtained from your carrier's merchant dashboard.
  5. In the **API Secret** field, paste your Secret Key or password (if required by the carrier; for PostNL, enter your standard API Key in the Username field and leave Secret empty).
  6. Click **Save**. The widget will automatically read this record whenever a user attempts to generate a shipping label!

Reference Table: Where to find your Carrier Keys

Carrier Required Identifiers Where to find in Carrier Dashboard
SendCloud Public Key & Secret Key Settings → Integrations → SendCloud API → Create new API credentials
MyParcel API Key (Token) Shop Settings → General → API Keys → Generate new API key
PostNL API Key (Token) PostNL Developer Portal → Applications → Your App → API Key
DHL API User & API Key DHL eCommerce Portal → Settings → API Integration → Active Keys

4. Technical Architecture & Module Mapping

During installation, the extension creates several underlying schema elements in your CRM database. Systeembeheerders should be aware of the following data structures:

  • Custom Button (Sales_Orders): A Web Tab / Embedded UI button named 🚚 Shipping & Returns placed in the detail view header of Sales Orders.
  • Custom Module (Carrier_Configs): Stores merchant API credentials. Contains fields: Carrier_name, API_Key_Username, and API_Secret.
  • Related List (Shipments / Attachments): The extension writes tracking metadata back to the related list of the Sales Order and uploads generated PDF labels directly into the native **Attachments** section.

Deluge Function Execution

The frontend HTML widget communicates with Zoho CRM via the official **Zoho Embedded App SDK 1.5**. When a user generates a label, the SDK triggers the backend Deluge function dispatchshipment:

// Example internal payload triggered by the SDK ZOHO.CRM.FUNCTIONS.execute("dispatchshipment", { "arguments": JSON.stringify({ "salesOrderId": "489201000000281001", "carrierName": "SendCloud", "packageType": "postnl:standard", "weight": "1.50", "deliveryType": "pickup", "servicePointData": "{\"id\":\"3533\",\"name\":\"PostNL Pakketpunt\"}" }) });

5. Troubleshooting Setup Errors

If end-users encounter errors during their initial testing, review the checklist below:

  • "No API Key found for SendCloud / Carrier": Verify that a record exists in the Carrier_Configs module and that the Carrier_name field is spelled correctly without trailing spaces.
  • "Zoho refused to execute the function": Go to Settings → Developer Space → Functions, locate dispatchshipment, and ensure the toggle "REST API / Widget Access" is enabled for all required user profiles.
  • PDF label does not appear in attachments: Verify that the user role has **Create/Upload Attachment** permissions on the Sales Orders module.
